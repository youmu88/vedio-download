# 视频库手工拷贝不可见 — 根因分析与修复交付

> 现象：手工拷贝视频（含文件夹下的视频）到 `downloads/<账号>/` 后，客户端刷新，浏览页看不到。
> 结论：**已复现并修复**。根因是 `/api/library` 只扫账号目录一层且把子目录当非文件丢弃；同一「name 就是单层文件名」的假设还散落在删除/转码/媒体探测三处，本次一并收敛到统一抽象。
> 复现/验收脚本：`scripts/repro-library-manual-copy.mjs`（临时 `VD_DATA_DIR`/`VD_DOWNLOADS_DIR`，不污染真实数据）。

---

## 1. 根因（A→B→C 链路）

调用链：前端 `loadLibrary()`（`public/js/macos.js`）→ `GET /api/library` → `fs.readdirSync(userDir)`。

**缺陷点 1（主因）：非递归读取 + 目录过滤**

- 修复前 `src/index.js:459` `fs.readdirSync(userDir)`：只列账号目录一层，不进入子目录。
- 修复前 `src/index.js:473` `return stat.isFile()`：读到子目录名也不是 file，直接丢弃。
- 结果：**子文件夹下的任何视频永远不会出现在列表里**，与文件格式无关。

**缺陷点 2：扩展名白名单窄于前端能力**

- 修复前 `VIDEO_EXTS = ['.mp4','.webm','.mkv','.mov','.m3u8']`（5 种）。
- 前端 `public/js/player-core.js:248` 的 `TRANSCODE_EXTS` 已覆盖 `.ts/.avi/.wmv/.flv/.mpg/.mpeg/.vob/.3gp`，即「前端有转码入口、后端不入库」——手工拷贝的 `.avi/.flv/.wmv/.mpg/.ts` 永远不可见。

**缺陷点 3（同类，修递归时必须同步）：name 被当单层文件名**

| 位置 | 修复前 | 子目录后果 |
|---|---|---|
| `DELETE /api/library/:name` | `path.basename(req.params.name)` | 删除被截成顶层同名文件 → 删错或 404 |
| `POST /api/transcode` | `path.basename(req.body.name)` | 子目录视频点「需转码」→ 404 |
| `GET /api/media-info` | `path.basename(req.query.name)` | 子目录视频可播性预判失效 |

**非缺陷项（已核实）**：`fs.watch` 递归监听（`src/index.js`）本已覆盖子目录事件并推送刷新 —— 用户看到的「刷新也没用」正是读取侧非递归所致；下载任务落盘始终在账号目录顶层，不受影响。

## 3. 修复内容

1. **新增 `src/library.js`（单一抽象）**
   - `VIDEO_EXTS`：14 种（`.mp4/.webm/.mkv/.mov/.m3u8/.avi/.flv/.wmv/.m4v/.mpg/.mpeg/.ts/.3gp/.vob`），覆盖前端 `TRANSCODE_EXTS`，同时作为 `fs.watch` 过滤依据。
   - `MAX_LIBRARY_DEPTH = 6`：递归深度上限（= name 最大路径段数）。
   - `resolveUserFile(userDir, name)`：相对 POSIX 路径 → 绝对路径；拒绝绝对路径、反斜杠、空段、`.`/`..`、超深、越界。删除/转码/媒体探测三处共用。
   - `listLibraryFiles(userDir, { isExcluded })`：递归扫描，name 为相对 POSIX 路径，按 mtime 倒序；跳过点开头文件/目录（含 `.vd-stream`）、符号链接、非常规文件、白名单外扩展名、`.part`/`.tmp` 临时文件；`isExcluded` 供「运行中任务 / 已入列表」过滤复用。
2. **`src/index.js`**
   - `/api/library` 改用 `listLibraryFiles`；运行中任务过滤只作用于顶层（任务产物只落顶层），收藏列表隐藏按相对路径（语义保持）。
   - `DELETE /api/library/:name`、`POST /api/transcode`、`GET /api/media-info` 改用 `resolveUserFile`（分类/穿越校验统一）。
3. **`src/list-store.js`**：`addItems` 条目名校验（拒 `../`、绝对路径、反斜杠、空段），条目名语义与视频库一致（相对路径）。
4. **`public/js/player-core.js`**：播放 URL 由整体 `encodeURIComponent` 改为**逐段编码**（保留 `/` 分隔符），子目录视频可被 `/downloads/...` 正常 Range 取流；删除 URL 保持整体编码（路由 `:name` 单段，`%2F` 由 Express 解码，已实测）。
5. **测试**
   - `test/library-scan.test.js`（8 用例）：路径解析安全边界、递归/深度/隐藏/符号链接/临时文件/白名单/排序/排除回调。
   - `test/library.test.js`（原 4 → 11 用例）：子目录递归可见、第 7 层不列出、白名单扩展、列表相对路径条目 + 隐藏语义、DELETE 子目录不误删顶层同名、穿越 400、media-info/transcode 相对路径、播放 URL Range 206。
   - `scripts/repro-library-manual-copy.mjs`：隔离环境复现 + 修复验收。

## 5. 边界与已知限制

- **深度上限 6 层**（`MAX_LIBRARY_DEPTH`，可按需调整）：更深目录的视频不列出。
- **符号链接不跟进**：防环与越出账号目录；真实目录不受影响。
- **点开头文件/目录一律不列出**：包含 `.vd-stream`（流式会话临时目录）与用户自己的隐藏目录。
- **`.ts` 入库**：整份 HLS 目录拷贝时，`.m3u8` 与分片 `.ts` 会同时出现（分片较多属预期）；播放 `.m3u8` 走 HLS 链路。
- **收藏列表隐藏语义保持**（用户确认）：已在列表中的条目不在浏览页重复出现。
- **删除路由仍按单段传参**：前端整体 `encodeURIComponent`（`%2F`），Express 5 解码后由 `resolveUserFile` 解析；若未来换框架需重新验证 encoded slash 行为。
