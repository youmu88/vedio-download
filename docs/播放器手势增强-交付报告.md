# 播放器手势增强 — 交付报告

> 需求：① 视频播放支持双指放大手势，等比放大撑满全屏（不扭曲）；② 横滑手势，右滑快进 / 左滑快退 15 秒。
> 追加需求：档位化缩放——获取屏幕比例，等比固定档自动适配屏幕（对齐主流播放器）。
> 日期：2026-10-14 ｜ 状态：✅ 完成并全部验证通过（首轮 23 项断言；档位化后 27 项断言）

## 〇、第二轮迭代：档位化缩放（自动适配屏幕比例）

**需求澄清**：16:9 视频不可能无扭曲「变成」16:10/4:3——主流播放器的「铺满全屏」本质是 **cover 铺满档**：短边撑满屏幕、长边超出裁切（16:9→16:10 仅裁 ~11%），画面内在比例不变、视觉零黑框且更大。屏幕比例可实时获取（全屏浮层 inset:0 即视口，`innerWidth/innerHeight` × `videoWidth/videoHeight`），无需特殊 API。

**实现**：连续捏合跟手不变，松手磁性吸附最近档位：

| 档位 | 定义 | 说明 |
|------|------|------|
| 原比例 | 1x | contain 完整画面（可能黑边） |
| 铺满全屏 | `coverScale = max(视口宽/内容宽, 视口高/内容高)` | 零黑框，长边裁切；随屏幕尺寸/视频分辨率实时计算，旋转自动适配 |
| 放大档 | `min(2×铺满, 4)` | 铺满后再放大的自由查看档（可平移） |

- 吸附时平移归中 + 0.26s 弹性过渡（transition 仅吸附期开启，新触摸立即接管不影响跟手）；指示条显示档位名（原比例/铺满全屏/放大 N×）
- 桌面滚轮无「松手」语义 → 连滚停止 350ms 后吸附；Safari 触控板捏合 gestureend 即吸附
- 捏合上限从固定 4x 改为动态放大档（小屏大裁切场景自然受限，避免无效放大）
- 验证：新增 4 项断言（中途松手吸附铺满档±0.06 + 零黑框 + 档位名、顶满吸附放大档、收拢吸回铺满档、桌面滚轮停止吸附），27/27 全绿；失败基线先行（4 项新断言红 → 实现后全绿）

## 一、交付内容

| 能力 | 行为规格 |
|------|----------|
| 双指捏合放大 | 等比缩放 1–4x（transform scale，数学上不可能扭曲）；指尖锚点缩放（放大朝手指中心汇聚）；内联卡片中双指外扩 → 播放器直接展开为全屏浮层并继续跟手缩放，直到内容撑满全屏（去黑边） |
| 双指收拢 | 缩小到 1x 后继续内收（收拢至捏合起距的 80%）→ 松手退出全屏回内联卡片，scale 复位 |
| 横滑快进/快退 | 视频面单指横滑（|dx|>|dy|×1.2 才激活，纵向让位页面滚动），每 64px 一步 ±15 秒，拖动中指示条实时显示「快进/快退 N 秒」，松手生效并夹取 [0, duration]；放大态（>1x）横滑为平移而非 seek（主流播放器惯例） |
| 双击 | 切换全屏/退出全屏（桌面鼠标无捏合时的等价入口） |
| 桌面端 | 触控板捏合（Safari `gesturechange` / Chrome `ctrl+wheel`）等价双指缩放；鼠标按住横拖等价横滑 seek |
| 状态自复位 | 切换视频 / 关闭播放器自动复位缩放、退出全屏、播放器节点归位 |

## 二、关键设计决策（为什么这么做）

1. **全屏 = CSS 固定浮层（`.fs`）+ 播放器节点临时迁移 body**，不用 `Element.requestFullscreen`：iPhone Safari 至今不支持该 API（`<video>` 原生全屏会被系统播放器接管，自绘手势全部失效）；CSS 浮层方案 media 元素在文档内迁移不打断播放，退出时按 `parent + nextSibling` 精确归位。
2. **独立手势层 `player-gestures.js`，PlayerCore 零改动**：手势通过 media 事件（`emptied`，PlayerCore 切换/关闭必经 `removeAttribute('src')+load()`）自管理生命周期，与播放核心完全解耦，双端（ios.html/macos.html）同一份代码，延续「消除双端漂移」的架构原则。
3. **Pointer Events 统一输入**：触摸/鼠标/触控笔一套代码；另挂 Safari 桌面 `gesturestart/change` 与 `ctrl/cmd+wheel` 两个触控板捏合适配器。
4. **系统手势让位**：起手 x<28px 的触摸不认领（与 ios.js 左缘返回手势带宽一致），系统级返回优先——iOS 惯例，已验证不破坏既有返回链路；视频底部 56px 控制条保护区不认领，避免与原生 controls 进度条二次 seek。
5. **直播流（duration 无穷）禁用 seek、保留缩放**；边转边播 seek 超出已转换范围时沿用 PlayerCore 既有提示链路。

## 五、已知边界（如实说明）

- 截图的视觉模型核验本次不可用（会话无 `image_parse` 工具），视觉证据为截图存在性/尺寸 + DOM 几何断言（等比、覆盖、z 层级均为机械断言）。
