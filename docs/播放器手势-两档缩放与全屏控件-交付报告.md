# 播放器双指缩放：两档收敛 + 全屏控件可见 — 根因与修复交付

> 反馈（第 6 轮）：① 要求两档但实际还有第三档、档位不清；② 从铺满档「缩一下」直接退出全屏，期望只回到全屏档；③ 撑满全屏后单指点击看不到进度条等控件（疑似被放大撑出去）。
> 结论：**三条全部真实复现并修复**。根因是用 `transform: scale()` 放大 `<video>` 元素实现「铺满」，而原生控件在其 UA 影子 DOM 内随元素一起放大出屏；同时 scale 是连续量产生中间档，`collapsed` 退出条件在从铺满档收拢时必然先满足。

---

## 1. 根因（三处，同一设计选择引发）

**主因：铺满档用 transform 缩放 `<video>` 元素**

- `public/js/player-gestures.js` 原 `apply()`：`video.style.transform = scale(${scale})`。
- 原生 `controls`（iOS/Chromium 都绘制在 video 元素内部）随之缩放：640×360 测试视频在 390×844 视口上铺满需 **3.0×**，元素盒变 1170×2532 → **控件被推出视口，点击画布看不到进度条**（实测 `video.getBoundingClientRect()` 四边全部溢出）。
- scale 是连续量：跟手中 `sx` 依次为 1.10 → 1.19 → 1.38 → 1.76 → 2.24 …，指示条显示百分比 —— 用户感知「还有第三档、档位说不清」。

**次因：`collapsed` 退出条件与降档条件冲突**

- 原逻辑：`s = pinchStartScale × d / d0`，`s ≤ 1.001 && d < d0 × 0.8` → 记退出意图，松手 `exitFs()`。
- 从铺满档（coverScale≈3.0）收拢时，`s` 降到 1 需要 `d/d0 ≤ 1/3`，此时 `d < 0.8·d0` **必然已成立** → 一次收拢直接退出全屏（实测：`大幅收拢被缩放手势退出全屏 = true`）。

**第三处：全屏时顶部栏被 `display:none`**

- `round2` 为修「bar 占 53px 文档流致顶部黑边」把 `.inline-player.fs .inline-player-bar` 设为 `display:none` → 全屏时**没有任何图标**可退出全屏（实测 `全屏时存在可点的退出/关闭图标 = false`）。

## 3. 修复内容

| 文件 | 改动 |
|---|---|
| `public/js/player-gestures.js` | **删除连续缩放体系**（`transform`/`setScale`/`coverScale`/`levels`/`snapToLevel`/`zoomTo`/`EXIT_RATIO`/`collapsed`/吸附 transition），改为两态 `class="fill"` 切换；双指外扩→铺满、收拢→全屏；**手势永不退出全屏**；仅全屏时响应缩放（内联不进入全屏）；桌面 ctrl+wheel / Safari gesture 按方向切档（阈值 + 切档后重设基准防抖）；切档提示不再被松手吞掉；全屏时左缘起手也由播放器接管（快退），非全屏仍让位系统返回手势；新增 `exitFullscreen(video)` 供页面图标调用 |
| `public/ios.html`、`public/macos.html` | `.inline-player.fs.fill video { object-fit: cover }`（只裁切画面内容，元素盒恒等于视口）；全屏顶部栏**浮层化**（`position:absolute` + 顶部渐变 + 安全区 padding），不占文档流（消除顶部黑边）且按钮可见；删除 `will-change: transform` |
| `public/js/ios.js`、`public/js/macos.js` | 顶部 close 图标：**全屏时 = 退出全屏回内联**（播放器不关闭），非全屏 = 关闭播放；`canIosBack()` 增加「全屏播放时禁用左缘返回手势」——否则全屏左滑会把页面导航走、播放器留在隐藏容器里（本轮举一反三发现的同类缺陷） |
| `scripts/player-gestures-verify.mjs` | 断言体系改为两态语义（object-fit/fill/元素盒/顶部栏几何），新增「控件在屏内」「图标退出全屏」「全屏左缘手势不导航」等用例，38 条 |
| `scripts/repro-pinch-round3.mjs` | 新增隔离复现/验收脚本（临时数据目录 + 独立端口 + 截图） |

**为什么这样更简单**：不再计算 cover 倍率、不再维护 scale 档位数组/吸附动画/退出意图状态机；档位就是两个 CSS 状态，控件布局完全交给浏览器。

## 5. 边界与已知限制

- **原生控件的显隐由浏览器/系统控制**（播放中会自动隐藏、点击唤出）：headless Chromium 截图里通常不绘制控件，测试以「元素盒 = 视口 + 底部控制区 `elementFromPoint` 命中 video」作为可点性判据；真机上控件位于视频元素内部即必然可见。
- **全屏时顶部栏浮层覆盖顶部约 50px**，该区域的点击由按钮栏承接（标准播放器行为）；底部 56px 仍为原生控制条保护区（手势层不认领）。
- **进入全屏的入口**：双击画面或（桌面端）双击；退出全屏：顶部 close 图标。手势不再承担全屏切换。
- 两档只改变画面裁切方式，**不缩放元素盒** —— 因此也不存在「拖动画面平移」的需求（画面始终居中）。
